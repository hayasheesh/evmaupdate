# EVデータ

シミュレーションのEVは、各stationの実際の充電セッションから作る。1件のセッションの到着時刻・滞在時間・充電量を組のまま使うので、何時に来た車がどれだけ停まり、どれだけ充電するかの関係は、そのstationの実データのとおりになる。

## 1日のEVの作り方

運用日は日本の暦で平日か休日かを決め、その区分のセッションと到着率を使う。

1. **到着**：各充電口で、5分ごとに到着が起きるかを抽選する。1口あたり1日の到着数は「1口1日あたりの到着 × 3」で、3は将来のEV普及の倍率である。時間帯の配分は、そのstationの同じ区分のセッションの到着時刻（1時間ごと）に従う。10口すべてが埋まっていれば、その到着は捨てる。
2. **セッションの割り当て**：到着した車には、同じstation・同じ区分で、同じ時台に到着したセッションを1件割り当てる。その時台のセッションが20件に満たなければ、前後1時間ずつ範囲を広げる。滞在時間と充電量は、このセッションの値をそのまま使う。
3. **電池と充電器**：電池容量（50〜120 kWh、平均81.4 kWh）と充電器の定格（11、19.2、27.5、50 kW）は、将来の車両を想定した分布から引く。
4. **到着時のSoC**：住宅の2局は、同じセッションのSoC_startを使う。これはデータの作成者が「すべてのセッションは95%で終わる」と置いて充電量から逆算した値で、計測値ではない。ほかの局は、EPFL DESL の Level-3 データ（DC急速充電、1,878件、2022-04〜2023-07）の到着時SoCの分布から引く。
5. **目標SoC**：到着時SoCに「充電量 ÷ その車の電池容量」を足す。100%と、滞在中に定格の0.8倍で充電して届く値を上限とする。
6. **0時に停まっている車**：同じ到着の仕組みを前日と前々日について流す。この間は制御せず、各車は到着から定格で目標まで充電する。0時の時点で残っている車を、そのときのSoCで初期の車とする。
7. **日をまたぐ車**：最後のステップより後に出発する車には、到着から定格で充電し続けた場合に最後のステップの終わりまでに届くSoC（目標SoCが上限）を、最後のステップでの目標として課す。これは翌日の0時に停まっている車の作り方（6.）と同じ仮定である。到着から最後のステップまで定格で充電しないと届かない車では、この値を0.001ポイント下げる。入札LPも同じ条件を課す。出発時SoCの達成率には、この車も最後のステップで数える。

入札・学習・評価は、すべてこの同じ予測からEVを引く。予測誤差の倍率はかけない。

## 仮定として置いているもの

- EVの充放電に損失はない。V2Gでは、出発時に必要な量を守る範囲で、SoC 0%まで放電できる。すべての充電器が双方向である。入札LPと環境は同じ仮定で計算する。
- 普及の倍率3、電池容量と充電器の分布、目標SoCの上限に使う0.8は、データから決めた値ではない。
- 到着の時間帯、滞在、充電量は2018〜2023年の米国とノルウェーのデータで、日本のデータではない。
- 充電量は実際に入った量である。Boulderのセッションの多くは満充電の前に出発しているので、運転者が必要とした量より少ない可能性がある。
