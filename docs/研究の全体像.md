# EV-VPPはload-following型の商品に参入できるか

## 主題

load-following dispatch signal型（EDC系）の指令では、EV-VPPの需給調整市場への参入は難しい。
どれだけ難しいか、それでも参入するなら何が起きるかを、入札から当日制御までを一つのシステムとして組んで測る。

対象商品は二次調整力②相当。短周期でエネルギー収支がほぼゼロになるAGC型ではなく、同じ向きの指令が続き、EVのSoCや出発時の要求と競合する指令を扱う。

MARLで制御する対象にできるのは、次の2つを満たす商品に限る。

- 指令がある。指令に追従する商品であること
- 自動応答の商品ではない。FCRのような自動応答の商品は、応動の要求が厳しすぎる

## 背景

- EV-VPPの入札・制御研究が対象にする商品は、AGCなどエネルギー収支がゼロに近いものが多い。
- 入札と制御を組み合わせる研究は既に多い。組み合わせたこと自体は貢献にしない。
- EDC系の商品を対象にした研究は少ない。
- 実際の指令系列を使う研究も少ない。多くはup/down/noへの離散化か、発動確率だけを使う。

## 貢献

### 貢献1　load-following信号がEV-VPPに与える難しさの定量化

難しいことは先行研究で理論上は分かっているが、シミュレーションで測ってどれだけ難しいかを示したものは見当たらない。

- 同じEV、同じstation、同じ市場判定に、種類の違う複数の指令を与えて比べる。
- 手法の良し悪しを除くため、別の商品を対象にした先行研究の制御手法を実装し、EDC系の指令で試す。
- どれだけ難しいかと、何が難しいかを分析する。

比べる量:

- 5分ごとの追従率と30分コマの合格率
- MARL出力そのものの追従誤差（MAE）
- 出発時SoCの達成率と不足量
- 物理的に追従不能だった失敗と、追従可能だったのに外した失敗の内訳
- BESSに要る電力、エネルギー、充放電量

難しさの原因は信号名で済ませず、指令の性質で説明する。候補は累積エネルギー偏差、同じ向きの指令の継続時間、変化速度、上げと下げの非対称、EVの到着・出発との時間の重なり。

### 貢献2　システムの設計と実演

入札器、MARL制御器、force充電、PCCのBESSをつないだシステムを説明し、7 stationと20 stationで通して動かす。

結果は次の3つに分けて出す。

- MARL自身の性能
- force充電を加えた性能
- BESSを含めた連系点の性能

### 貢献3　MARLで市場に参入するときの難しさ

MARLでEV-VPPを制御し、市場の要求に照らしてどこまで届くかを示す。難しさを信号側と制御側に分けて分析する。

主張は「MARLを使うべき」ではなく「MARLを使ったらどうなるか」。MARLは現実の状況に合う利点を持つが、市場が要求する精度を出せるかは分かっていないので、実際に測る。MARLの達成精度は入札で変わるため、MARL用の入札器も作った。

照らし合わせる要求は日本の二次②の合格条件。ほかの市場の要求（デンマークのP90など）にも届かないかは未確認。

## 提案システム

| 層 | 役割 |
|---|---|
| EV状況予測器 | 各stationのEV到着時刻、初期SoC、必要SoCの分布を作る。学習用の分布を作るのが目的なので、精度は高くなくてよい。現状は、各stationの実セッションを平日・休日に分けて引くシミュレータで代用する。[EVデータ](EVデータ.md) |
| 入札器 | 予測分布と過去の実指令から、EV群が物理的に追従できる範囲で供出容量が最大の入札（30分コマごとの基準値・上げ幅・下げ幅）を決める。[入札器の問題設定](入札器の問題設定.md) |
| MARL制御器（既発表） | station単位のagentが、指令とローカル観測から充放電を決める |
| force充電 | 出発時SoCを達成不能にする行動だけを直す |
| PCCのBESS | EV群全体に残った追従誤差を吸収する。500 station換算で2 MW未満に抑える（特別高圧の境界） |

指令は予測しない。過去の実指令を使う。使う指令は[指令データ](指令データ.md)にまとめた。

入札と制御は互いに影響する。入札量が学習の前提になり、下位の実力が入札できる量の上限になる。
既存の方式は入札から制御への一方向で、制御の都合を入札が受け取れない。本研究では、EV数と指令の不確実性を入札器が、残りの誤差をMARL・force充電・BESSが受け持つ。
現状、制御側から入札へ戻している量は、下位制御器が保てる最小の帯幅（最低入札量を決める）だけ。

時間の流れ:

```text
数か月前   予測器と入札器を校正する。MARLを複数のEV × 指令で事前学習する
前日       EV状況を予測して入札する（入札受付 11:30–14:00、約定通知 15:00）
当日       事前学習したMARL、force充電、BESSで制御する
```

約定後に当日向けの追加学習（fine-tune）をする構成は、効果がほぼ出なかったため使わない。

## 分散制御を使う理由

市場に入札するのはアグリゲーターだが、EVを動かす権利は各stationが持つと想定する。
stationはアグリゲーターのインセンティブが見合えば従い、見合わなければ従わない。

中央観測のルールベース制御は性能が高く、遅延もプライバシーもほぼ問題にならない。ただし全stationが中央の目標に従うことが前提になる。
実際には自分の都合（早く充電したいなど）を優先して従わないstationが出るので、完全に分散した制御が要る。

詳細と計算時間の実測は[分散制御を使う理由](分散制御を使う理由.md)。

## 比較するもの

- 指令: エネルギー収支が小さいAGC型と、load-following型
- 層ごとの効果: `marl_raw`、`marl_force`、`marl_force_bess`
- 中央観測ルールベース `rule_based_central`: 全stationが中央の目標に従う場合の上限。actorは使わない
- 先行研究方式: 調査して選んだ別商品向けの入札・制御方式。中央LPで代用しない

中央残差分配は提案システムに入れない。中央残差分配やBESSを通した後の値をMARLの性能とは呼ばない。

## 規模

主な評価は7 stationと20 station。500 stationは計算時間の確認にだけ使い、学習済み性能の主張には使わない。
