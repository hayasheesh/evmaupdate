# 分散制御を使う理由

## 速さやプライバシーは理由にしない

中央観測のルールベース制御（中央残差分配）は、stationが公開する柔軟性の範囲を集め、中央でstation別の電力目標を決める。
500 station、各10 EVでもforce充電込みで約1.1秒/stepで、5分周期に収まる。交換するのはstation単位の集約値だけなので、通信量も小さい。

したがって「中央方式は遅い」「中央方式はプライバシーを損なう」ことをMARLの根拠にしない。

## 制御権の想定

市場に入札するのはアグリゲーター。EVを動かす権利は、アグリゲーターとやり取りする各stationが持つ。

stationは次の事情から、中央の目標に従うとは限らない。

- 利用者が早く充電したい
- 事業車など、出発時のSoC不足で失うものが大きい
- 提示されたインセンティブが見合わない
- stationごとに利用者の構成と、許せるSoC不足が違う

中央ルールベースは「全stationが中央の目標に従う」ことを前提にするので、この想定の下では現実的でない。
提案するMARLは中央からstation別の目標を配らず、各stationがローカルの状態から行動する。論文ではこの点を強調する。

中央ルールベースは、全stationが従う場合の性能上限として比較に残す。

## 未実装：stationのポートフォリオ

現状の実装は分散実行までで、インセンティブへの応答（従う、従わない、一部だけ従う）はモデル化していない。そのため、今のところMARLの必要性を性能差だけでは示せない。

今後、stationの特性をポートフォリオとして設計し、全体に組み込む。少なくとも次の違いを表す。

- SoC達成を強く要求する事業車中心のstation
- 多少の不足を許せる一般利用中心のstation
- インセンティブに敏感なstation
- 充電完了を優先し、中央の要請を断りやすいstation

型ごとに、インセンティブ、断る確率、SoC不足のコスト、接続時間を分ける。関数の形は先行研究を調べてから決める。

## 計算時間と応答時間

指令間隔は5分。1周期の予算を210秒とし、残り90秒を機器側の整定の余裕とする。

| 項目 | 値 | 出所 |
|---|---:|---|
| 通信と機器応答（状態取得、モード変更、電力設定の最大の合計） | 26.84 s | IEEE Access論文のIoT-HUB実証。対象は定置用蓄電池で、EVSE固有の整定時間は未確認 |
| MARLのactor順伝播、7 station | 平均 3.45 ms | 実測 |
| MARLのactor順伝播、20 station | 平均 12.61 ms | 実測 |
| force＋中央配分、500 station × 3 EV | 452 ms/step | 実測 |
| force＋中央配分、500 station × 10 EV | 1,096 ms/step | 実測。うちforce約1,045 ms、中央配分約49 ms |

forceはPythonでEVを1台ずつ処理しているため、中央配分より遅い。

出典: Hayashi et al., Hierarchical Multi-Agent Reinforcement Learning Control for EV VPPs, IEEE Access, Section VI, Table 5, Fig. 7（`docs/IEEE_ACCESS.pdf`）
