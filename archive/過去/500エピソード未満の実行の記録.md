## 事前学習済みの方策に対する1日分の追加学習（ft_a1〜a7、9/17）

- 対象日：2024-12-04

- 選択：holdout の指令24本で、追加学習前後の系全体の追従率を比べる

| 実行 | 変えたもの | 結果 |
|---|---|---|

| a3 | 学習率10倍 | 94.99〜95.04。候補なし。離脱時の不足が増えた |

- a1〜a3 は、学習器が最適化している量（補正前の追従率、MAE）では改善した。一方で、補正後の追従率は上がらないか下がった。
- a6 と a7 では、初期化の直後に、行動器に入る local と global の勾配の余弦が −0.75 と −0.64 まで下がり、同時に方策が崩れた。
- 6通りとも、追加学習前の方策を超えなかった。これを受けて、日ごとの追加学習を本線から外し、コードを `legacy/finetune` に移した。

## 報酬の形の比較（run B と legacyrw、9/17〜18）

### gamma_noalloc_7station_7station_20260917_181704（run B）

- 設定：中央残差配分なし、報酬は `bounded_absolute_error`（誤差スケール150 kW）、最低入札量250 kW、bank は `train_25_fixed_ev_256_all_commands`、勾配クリップ5.0
- 結果：ep440 で追従率78.4%、SoC 71.1%（和149.6）
- やめた理由：ep115 から global critic の勾配がクリップ5.0に当たり始めた。直近のクリップ率は0.39〜0.45、最大0.66だった。hobo100100 は1821エピソードでクリップが一度も発動していなかったので、報酬の桁を hobo100100 に合わせる試行に移った。

## 20局での事前学習（prod_s20b_20station_20260919_152839、9/19〜20）

- 目的：7局でルールベースが MARL を上回るのが、規模が小さいせいかどうかを見る
- 設定：20局、`legacy_tolerance_band`、帯の外の傾き0.00896/kW、global のクリップ20.0、局に共通の雑音あり（gain 1.0）、蓄電池105 kWh / 80 kW、bank は `train_25_20s_f500`
- 結果：ep480 で追従率73.7%、SoC 70.9%（和144.6）。最良は ep460 の146.7
- やめた理由：9/20 01:16 に ep480 で停止した。その後、指令の発動頻度が低すぎることが学習を妨げているという診断に移り、報酬を `bounded_absolute_error`、指令を dense8、最低入札量を500 kW に変えた7局の学習を優先した。20局はそれ以降再開していない。
- 20局で学習した実行は、これだけだった。

## 短い学習で基準の性能を出す試み（9/25）

基準は AB の ep1300 の値（追従率＋SoC の試験5回平均で159.4）とした。
noalloc は ep800 でこれに届いた。

### noalloc_fast_t1_x3

- 設定：noalloc の設定で、学習率3倍（行動器3e-6、critic 9e-6）、τ 3倍（0.003）、ε は ep333、雑音は ep500 で下げ終える、全600エピソードの予定
- 結果：追従率は noalloc を3倍の速さにした見込みどおりに上がった（ep200 で85.8%）。SoC は ep40 から40%前後のままで、ep200 で43.7%だった。noalloc の ep600 は64.7%
- critic の値（Q の global と local、勾配の比）は、noalloc の3倍のエピソードの値とほぼ一致した。行動器の勾配のクリップ率は8%で、noalloc の同じ段階（3%）より高かった
- やめた理由：ep205 で試験5回平均の和が127.7（noalloc の ep600 は150.1）で、SoC が戻る兆しがなかった

### noalloc_fast_t2_utd3

- 設定：学習率と τ は noalloc と同じ、1ステップあたり3回更新、ε は ep333、雑音は ep500 で下げ終える、全400エピソードの予定
- 1エピソードは約106秒で、1回更新のときの約2倍だった
- やめた理由：更新の回数を増やすと1エピソードの時間が延びるので、エピソード数が減っても学習にかかる時間は短くならない。ep10 で止めた
