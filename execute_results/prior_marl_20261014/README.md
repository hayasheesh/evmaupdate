# MARL-AFMの制御アルゴリズムの適用

このフォルダは原著の全処理を含まない試作であり、論文の先行研究の再現結果には採用しない。上位の入札Actorなどの未実装がある。87回の学習状態を保存して停止した。`EXCLUDED_FROM_PAPER.json`により、この実行の自動再開と結果の採用を止める。完全性の確認は `docs/論文結果のアルゴリズム監査_20261014.md` に記載する。

[WangほかのMARL-AFM](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6229136)から、動的グループ分け、グループの参照指令、局所EV Actor、多頭attentionのCritic、DDPG更新を本研究の環境に移植した。入札には本線と共通の入札を使う。報酬は本研究の追従・充電報酬を使い、重みを検証用データで選ぶ。

本研究の環境で制御アルゴリズムを適用した成績として報告する。原著の市場入札を学習するActorは、この比較には含まない。

## 適用する条件

| 項目 | この実装 |
|---|---|
| データと入札 | 6 station AEMO。本線の学習25日・検証5日の入札を共用する |
| 動的グループ | 各stationで、充電不足かつ残り1時間以内、その他の充電不足、充電不足なしの3群。毎時刻に分類する |
| 参照電力 | 中央が全EVの現在の実行可能な充放電範囲を集め、全体指令に対応する割合を各EVの範囲に当てる。参照電力はActorの入力にする |
| Actor | stationごとに独立したネットワーク。station内のEVで重みを共用する。EV自身、stationの公共情報、所属グループの要約、参照電力を観測する |
| Critic | 全体の状態・行動をグループで集約し、多頭attentionから1つのQ値を出す。学習時だけ使う |
| 学習 | DDPG。割引率0.99、target更新率0.005、Actor学習率0.0001、Critic学習率0.001、batch 256、buffer 100,000 |
| 報酬 | 大域報酬＋重み×本線の局所報酬倍率×stationの局所報酬の平均 |
| 評価 | GLOBAL、LOCAL、その和、MAE。市場の判定は最終の40組で別に報告する |

参照電力を作る中央の処理は、現在の全EVの実行可能範囲を使う。この情報条件も方式の一部として報告する。本線の分散Actorにはこの処理を追加しない。

グループの閾値、参照電力の配分、ネットワーク幅、team rewardの構成は今回の適用条件である。原著のDDPG更新式とattentionを使う構成は本文で確認した。buffer容量は表2の100,000を使う。図3は10の6乗と記載されている。[外部一次資料・コード確認]

## 報酬の重みを選ぶ手順

重み0.5・1・2を、それぞれ同じseed 141026で200回学習する。最後の検証用5エピソードでGLOBAL＋LOCALが最大の重みを選ぶ。同点なら小さい重みを選ぶ。検証seedは910000で固定する。

200回の比較は報酬調整用である。選んだ条件を初期状態から2,000回学習し、学習に使わない指令4本・EV seed2通り・検証日5日の40組で評価する。最終の40組は、報酬の重みの選択には使わない。

各モデルのソースと設定は学習archiveのmethod_sourceへ保存する。ネットワーク、optimizer、replay、RNGを保存して、温度停止後に完全再開する。設定はmethod_config.json、比較結果はreward_trials.json、選んだ条件はselected_reward.jsonに記録する。

## 実装と確認

adapted_agent.pyが学習器、stage_worker.pyが環境への接続、run_pipeline.pyが報酬比較・本学習・最終評価の実行順を管理する。温度監視は既存の90°C条件を使う。

演算部品と適用学習器のテスト10件が通過した。確認したのは、未接続EVのpadding、EV順序に対する対応、中央の参照電力、学習勾配、ネットワーク更新、保存後の次の更新の一致である。評価成績は学習完了後に記録する。[コード確認]
