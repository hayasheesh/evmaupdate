# MARL-AFMの実装仕様

対象はWangらの[SSRN 6229136](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6229136)である。全文は `../prior_marl_20261014/source/ssrn_6229136.pdf` に保存している。原著に記載された構成を実装し、一意に定まらない部分は以下の仕様で補う。著者のソフトウェアとの一致や、原著の数値結果の再現は未確認である。

## 原著と実装の対応

| 原著の記載 | 実装 | 本文にない補完 |
|---|---|---|
| 表1・3.2.1節の上位入札Actor | `BidActor`。各コマの基準値、energy価格、上げ容量、下げ容量、容量価格、mileage価格の6出力 | 全日の予測特徴と各コマの特徴を入力する共有MLP |
| 表1・3.2.1節のEV Actor | `ControlPolicies.ev_actor`。EV自身、stationの観測、所属群の要約、参照指令、incentive tariffを入力 | EV間でパラメータを共有。隠れ層64を2層。tariffの生成式は未記載なので上位のenergy価格出力を使う |
| 3.2.2節の動的群分け | `DynamicGroups`。各時刻にSoC不足、出発までの時間、stationから所属を決める | stationごとに「不足あり・残り12ステップ以下」「不足あり・それ以外」「不足なし」の3群。群の番号は固定し、EVの所属が変化する |
| 3.2.2節の群の要約 | EV特徴の平均・最大、接続台数、station、群の種類 | 平均と最大を両方使う。空の群をattentionから除く |
| 3.2.2・3.3.2節の参照指令 | `reference_actor` が群ごとの指令を学習。各EVの物理的な上下限へ写す | 上位の参照指令をsigmoidで0〜1にし、そのEVの上下限の間の割合として使う |
| 図4の群の局所Critic | `local_critic`。EVごとの状態・群・参照・行動からQ値を計算し、群内で平均 | 群のCriticの重みを共有。EVの出発時SoC報酬と指令への追従罰則を学習する |
| 3.2.3節の多頭attention | 大域tokenと群tokenに4頭のscaled dot-product attentionを適用 | tokenに群のQ値・行動・参照を含める。大域tokenの出力を使う |
| 図4の非単調な大域混合 | attentionの特徴と各群のQ値を、符号を制限しないMLPに渡す | attention→混合の順。隠れ層128を2層 |
| 3.4節・式13〜15の更新 | replay、MSEのTD誤差、deterministic policy gradient、soft target update | 下位は大域Qと個別Qを足した目的で更新。参照Actorにも下位応答を通して勾配を返す |
| 3.3.3節の入札と制御の接続 | 予測→入札Actor→約定容量と指令→EV制御→状態と報酬→更新 | 前日の入札は日中に固定する。上位は1日分の割引報酬を受ける終端遷移、下位は5分の遷移を使う |

原著は群分けの具体的な規則、参照指令の生成式、attentionと図4のCriticの接続、上位と下位の更新時刻を一意に定めていない。この表の補完仕様は、本実装の再現に必要な条件として保存する。

## 環境と報酬

EVデータ、目標SoC、時間刻み、入札時の予測、指令、最低入札量、アセスメントIの余裕は本研究の環境を使う。予測特徴と供出可能量の上限は同じEV予測から取り出す。Bendersが計算した基準値・入札量は、入札Actorの教師にも出力の代用にも使わない。

本研究の市場モデルは価格による落札を扱わず、供出量を全量約定する。6つの出力のうち価格3項目は記録するが、約定量と報酬は価格で変わらない。価格による市場清算の再現結果には使えない。価格清算を新たに作るには市場モデルの変更が必要になるため、この実装の測定対象は量を決める入札と当日の制御である。

個別EVの報酬は現在のSoC進捗・出発時の報酬に群の参照指令との差を加える。上位の日報酬は現在の大域報酬、正規化した入札容量、stationのSoC報酬を使う。報酬の重みは本研究の検証用データで選ぶ。原著の経済報酬や重みを再現した値としては報告しない。

gamma=0.99、tau=0.005、Actor学習率=0.0001、Critic学習率=0.001、batch=256、replay=100,000は表2を使う。本文の図3にはreplay=1,000,000という別の記載がある。実装は表2の値を採る。勾配clipは5で、本線のQ_MIXとclipは変更しない。

## 実験と保存

学習用25日、検証用5日を使う。検証指令と最終40組の指令を学習から除く。検証のEV seedは910000＋日番号、最終評価は本研究の固定した40組を使う。検証による乱数状態とreplayの変化を防ぐ。

報酬候補は局所倍率0.5・1・2について200回ずつ試し、同じ入札での検証GLOBAL＋LOCALを使って選ぶ。候補の200回は報酬選択のための実行で、論文のMARL結果には使わない。選択した条件を新規に10,000回学習する。保存点の選択と収束の確認には検証結果を使い、最終40組を使わない。

入札Actorを使う評価と、制御比較のために共通入札を渡す評価を別に保存する。共通入札の評価ではGLOBAL・LOCAL・MAEを比べる。自方式の入札を使う評価には入札容量も併記する。追従するコマがない組のGLOBALは欠測として扱う。

完全再開用に全Actor/Critic、target、optimizer、2種類のreplay、乱数状態、完了した学習回数を保存する。ソース・データ・正規化・設定が保存時と一致しない場合は再開しない。EVの次のQ値は、station・EV id・到着時刻が一致したEVに対応付ける。出発やEVの入れ替わりをまたいで、別のEVのQ値を継続値に使わない。

このフォルダの実装と検証状態は `implementation_status.json` に保存する。停止した制御のみの試作は `../prior_marl_20261014/EXCLUDED_FROM_PAPER.json` により引き続き除外する。
